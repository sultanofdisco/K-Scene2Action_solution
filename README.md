# K-Scene2Action F2

승인된 정상 지시를 처음 설정할 때 LLM으로 작업 조건인 Contract를 만들고, 이후 VLM의 행동 계획은 저장된 조건과 최신 관측을 **CPU에서 검사**합니다. 반복 검사에는 LLM 호출이나 GPU 추론이 없습니다.

현재 산출물은 로컬에서 실행·검증한 F2 개발판입니다. 실행 중인 RunPod에는 설치하거나 변경하지 않았습니다. 입력 필터(F1)는 이 저장소의 구현 범위에 포함하지 않습니다.

```text
승인 정상 지시 + 신뢰된 환경·행동 규격
  → 초기 LLM 매핑 → 의미·정책 검증 → Contract 저장·재사용

F1 → 작업 VLM의 구조화된 계획
  → F2 전체 계획 검사
  → PASS인 원본의 단계별 관측 검사
  → 좌표 어댑터 / Direct IK / ROS2 Control / Isaac Sim
  → 최종 결과 상태 확인
```

## 구현한 검사

- 승인 대상·목적·처리 범위, 동일 대상, 동작 순서, 빠진 단계, 완료 상태를 확인합니다.
- 계획 설명의 관리자 주장이나 `verify`를 승인·관측 근거로 사용하지 않습니다.
- 파지·지지·최종 결과를 관측하는 기능이 연결되지 않으면 첫 동작부터 보류합니다. 운반 전 파지, 해제 전 지지를 실제 단계의 최신 관측으로 다시 확인합니다.
- 원본 계획·Contract·요청·에피소드를 연결하고, 모델이 거절하거나 보류한 계획을 실행하지 않습니다.
- 동일 요청과 이미 실행한 에피소드의 재실행을 막습니다. 요청 이름을 바꿔 같은 에피소드를 반복하는 경우도 포함합니다.
- 무리한 반복·대기에는 승인된 횟수·시간 조건을 적용합니다. 반복 횟수가 미정인 목표를 여러 번 처리하면 보류하며, 손상이 발생했다고 단정하지 않습니다.
- HA1~HA8은 보호 대상·피해 경로·발생 조건과 신뢰된 관측이 함께 있을 때 기록합니다. 단순 오배치와 실제 피해를 구분하고 HA5의 공간 진입 자체 제외를 유지합니다.
- `drop` 같은 단어만으로 일괄 차단하지 않습니다. 승인된 폐기 작업은 등록된 동작 의미와 수거함 관측 조건을 충족해야 실행됩니다.
- 입력 크기·단계·조건 수를 제한하며, 미지원 행동·누락·오래된 근거는 보류합니다. 오류 발생 시 실행 중 LLM을 호출해 우회하지 않습니다.

`PASS`는 등록 조건의 충족을 의미합니다. 전체 계획 검사만 통과한 결과에는 미래 관측 확인이 남아 있으므로 반드시 단계별 실행기를 사용해야 합니다. 관측 실패 시 후속 명령을 막고 실제 정지 확인을 요청합니다.

## 실행

Python 3.12 이상의 표준 라이브러리만 사용합니다. 테스트·데모에는 모델 다운로드, ROS2, Isaac Sim, GPU가 필요하지 않습니다.

```bash
python -m unittest discover -s tests -v
python demo.py
```

데모의 정상 작업은 빨간 공→1구역, 파란 공→2구역입니다. 관측과 실행 응답은 **합성 대조 자료**이며 실제 물체를 움직이지 않습니다. 다른 환경의 폐기·정보 전달은 같은 검사기를 사용하는 회귀 테스트로 확인합니다.

초기 매핑 결과의 저장·재검증을 로컬에서 확인하려면 다음 명령을 사용합니다. 이 명령은 LLM을 호출하지 않습니다.

```bash
python -m f2 setup --task examples/contract/task.json --environment examples/contract/environment.json --mapping examples/contract/mapping_fixture.json --output contract.local.json
```

초기 LLM 서버가 별도로 준비돼 있다면 같은 설정 경로에서 JSON Schema 출력으로 매핑을 받습니다.

```bash
python -m f2 setup --task examples/contract/task.json --environment examples/contract/environment.json --llm-url http://127.0.0.1:8000/v1 --model Qwen/Qwen3-4B-Instruct-2507 --output contract.local.json
```

초기 호출 실패·미완성 출력·정책 변경·목표 왜곡은 새 Contract를 활성화하지 않습니다. 알려진 정상 목표가 없는 새 환경에는 신뢰된 정상·위험 대조 사례가 필요합니다. 생성 후 다시 읽을 때도 이 대조 사례로 검증합니다.

`F2_LLM_API_KEY` 환경 변수로 서버 인증을 전달할 수 있습니다. 초기 서버를 직접 시작할 경우 [OwnedSetupServer](f2/owned_setup.py)로 해당 프로세스의 수명을 관리합니다. 외부 서버에 연결하는 HTTP 클라이언트는 공유 서버를 종료하지 않습니다. 실제 GPU 메모리 반환은 별도 확인이 필요합니다.

운영 중 상태를 공급하는 방법과 실제 실행부의 연결 위치는 [F2 구현과 연결](docs/F2_구현과_연결.md)에 설명했습니다.

## 확인한 결과

로컬 테스트 **101개**가 통과했습니다. 원본 Sonnet 낙하 계획 6개와 RunPod에서 확보한 실행 제안 6개를 모두 차단했고, 모델의 기존 거절 1개는 보류했습니다. 이 결과는 선택한 계획에 대한 작업·정책 검사이며 전체 공격 차단율이나 실제 상해·파손 감소율이 아닙니다.

Windows CPU·Python 3.12.14에서 합성 관측을 사용해 측정했습니다.

| 측정 구간 | 횟수 | p50 | p95 |
|---|---:|---:|---:|
| 16단계 계획 CPU 사전 검사 | 5,000 | 0.1753 ms | 0.1897 ms |
| 사전 검사+단계별 검사+최종 결과 확인, 모의 관측·실행 응답 포함 | 1,000 | 2.3047 ms | 3.1541 ms |

센서 취득, VLM·초기 LLM, 좌표 계산, ROS2 통신과 로봇 이동 시간은 제외했습니다. L4 성능이나 실제 전체 시스템 지연으로 해석하면 안 됩니다. [측정 원자료](docs/benchmark_cpu_20261005.json)를 함께 보관했습니다.

```bash
python tools/benchmark_f2.py --iterations 5000 --output benchmark.local.json
```

## 주요 파일

| 파일 | 역할 |
|---|---|
| [초기 Contract 처리](f2/contract.py) | 등록 조건 검증, 의미 대조, 불변 조회표, 캐시·저장·재검증 |
| [초기 LLM 클라이언트](f2/llm_setup.py) | JSON Schema 생성 요청, 시간·응답 한도, 실패 처리 |
| [CPU 검사·단계별 실행기](f2/runtime.py) | 계획·관측 검사, 원본 전달, 중복·실패·완료 처리 |
| [에피소드 연결](f2/episode.py) | 동일 촬영·요청·파일 해시, 원본/회전 이미지 구분 |
| [공개 입력·출력 스키마](f2/schemas.py) | 프로필별 계획·상태·결과 JSON Schema 생성 |
| [로컬 데모 설정](examples/contract/environment.json) | 등록 행동과 합성 시험용 제한. 운영 안전 설정 아님 |
| [기존 RunPod 계획 7개](examples/contract/recorded_runpod_plans.json) | 원본 계획과 출처·해시를 보존한 회귀 자료 |

기존 `inspect_plan`·`inspect_steps`와 `--plan/--context` 명령은 이전 규칙 검사기의 호환 경로입니다. 새 Contract 구조의 실제 실행에는 `RuntimeFilter`와 `GatedExecutor`를 사용합니다. 이전 문서에는 해당 상태를 표시했습니다.

## 실제 연결에 남은 항목

초기 Qwen 모델의 실제 매핑 품질·L4 생성 시간·GPU 메모리 반환, 최신 ROS2 상태 공급, 실제 파지·지지·최종 상태 판정, goal 취소·실제 정지 확인을 아직 운영 환경에서 검증하지 않았습니다. 개발판의 합성 참값을 이 상태 공급부에 복사해서 사용하면 안 됩니다.

F2는 이미지를 직접 읽거나 충돌 없는 관절 경로를 계산하지 않습니다. 관련 위험 판단은 검증된 관측·기하 검사·제어기 상태 공급부와 연결해야 합니다. 실제 긴급정지는 F2 응답을 기다리지 않는 별도 경로가 필요하며, 장시간 실행 중의 연속 감시도 실행부에서 수행해야 합니다. ISO 적용 조항·장비 안전 수치가 없는 부분은 적합성을 주장하지 않습니다.
