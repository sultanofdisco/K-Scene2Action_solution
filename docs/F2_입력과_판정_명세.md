# F2 입력과 판정 명세

> 이전 규칙 검사기 기록입니다. 현재 Contract 구조·검증 상태는 [F2 구현과 연결](F2_구현과_연결.md)을 기준으로 봅니다.

행동 계획 검사(F2)는 비신뢰 VLM 계획과 신뢰된 작업·환경 정보를 별도로 받는다. 두 입력을 합쳐 모델에게 안전 선언을 맡기지 않는다. JSON 예제는 [정규화된 계획](../examples/plan_pass.json), [기존 VLM 형식](../examples/vlm_steps_pass.json), [환경 설정](../examples/context.json)에 있다.

## 입력의 책임

| 입력 | 제공 주체 | 필수 내용 |
|---|---|---|
| 행동 계획 | VLM | 실제 후보 행동, 대상, 목적지. 자유 문장을 실행 명령으로 해석하지 않음 |
| 작업 | 운영자·실행 서버 | 각 대상 ID, 목적지 ID, 승인된 배치 횟수 |
| 대상 상태 | 관측부·운영자 | 식별·접근 권한·파지 가능성·물체별 힘 상한·접근 경로 |
| 공간 상태 | 관측부·환경 설정 | 배치 허용 여부, 지지와 안정성 확인 |
| 경로 근거 | 독립적인 경로 평가·운영자 검증 | 출발·도착 ID, CLEAR/HAZARD/UNKNOWN, 위험 근거 |
| 실행 상태 | 로봇 제어기·실행 서버 | 오류, 안전 기능 상태, 초기 위치, 빈 그리퍼 상태 |
| 제한값 | 운영자 | 힘·속도·시간·횟수 상한과 설정 근거 |

카메라 한 대로 관측할 수 없는 값은 측정값처럼 채우지 않는다. 설정 또는 별도 검증으로 확인할 수 없는 필요한 상태는 미확인으로 두고 보류한다. 모델의 `verify` 명령을 받았다는 사실만으로 실제 관측 확인을 참으로 바꾸지 않는다.

## 정규화된 계획

루트 필드는 `schema_version`, `request_id`, `context_id`, `environment_version`, `actions`로 한정한다. 버전은 `1.0`이다. 세 ID는 신뢰된 환경 정보와 정확히 같아야 한다. ID 일치는 인증이나 무결성 서명을 뜻하지 않는다.

| 행동 | 정확히 필요한 추가 필드 | 의미 |
|---|---|---|
| `pick` | `target_id`, `grip_force_n`, `duration_s` | 대상 파지. 등록된 접근 경로도 확인 |
| `move` | `destination_id`, `route_id`, `speed_m_s`, `duration_s` | 보유 대상을 등록된 경로로 운반 |
| `place` | `target_id`, `destination_id`, `duration_s` | 같은 대상을 도착 위치의 지지면에 배치·해제 |
| `wait` | `duration_s` | 제한 시간 안에서 대기 |
| `finish` | 없음 | 배치 완료·빈 그리퍼 상태로 계획 종료 |
| `stop` | 없음 | 단독 보호 정지. 작업 완료로 집계하지 않음 |

모든 행동에는 `type`이 있다. 시간·힘·속도는 유한한 양수이고 문자열·불리언을 숫자로 취급하지 않는다. 미등록 ID·필드·행동을 자동으로 고치거나 추측하지 않는다. 작업에는 반드시 종료가 있고 종료 뒤 행동을 허용하지 않는다.

힘은 물체 상한과 전체 상한 중 더 작은 값으로 검사한다. 보유 시간은 파지부터 배치까지 계획 시간을 보수적으로 합산한다. 실제 시간·힘·속도를 측정하는 기능은 포함하지 않는다. 실행부가 상한을 유지하고 시간 초과에 대응해야 한다.

## 환경 정보와 값

| 항목 | 필드 | 예제 설정 |
|---|---|---|
| 준비 상태 | `context_status` | `READY` |
| 승인 작업 | `task.target_id/goal_region_id/placement_count` | `red_ball/zone_1/1` |
| 대상 근거 | `objects[id].authorized/observed/graspable` | 모두 실제 불리언 |
| 물체 힘 상한 | `objects[id].max_grip_force_n` | `4.0` N |
| 접근 경로 | `objects[id].approach_route_id` | `approach_red` |
| 배치 근거 | `regions[id].placement_allowed/support_verified/stable_verified` | 모두 실제 불리언 |
| 경로 연결 | `routes[id].source_id/destination_id` | 출발·도착과 일치 필요 |
| 경로 판정 | `routes[id].assessment/hazards` | `CLEAR`와 빈 위험 목록, 또는 근거 있는 `HAZARD` |
| 실행 상태 | `execution.state/holding/location_id` | `ready/null/home` |
| 제어기 상태 | `execution.robot_error/safety_enabled` | `false/true` |
| 전체 제한 | `limits.max_actions/max_duration_s` | `12/30.0` s |
| 운동·파지 제한 | `limits.max_speed_m_s/max_grip_force_n` | `0.1/8.0` |
| 보유 제한 | `limits.max_hold_time_s` | `10.0` s |

여러 대상은 `task.placements`에 `target_id/goal_region_id/placement_count` 항목을 나열한다. 같은 대상의 중복 항목은 보류하며, 배치 횟수는 양의 정수다. 한 대상 작업은 기존 세 필드 형식도 지원한다. [두 공 예제](../examples/context_two_balls.json)는 빨간 공과 파란 공을 각각 한 번 배치하도록 승인한다.

경로의 `source_id`가 이전 상징적 위치와 맞지 않으면 보류한다. 이것은 실제 위치의 기하학적 일치를 계산한 결과가 아니다. 계획·관측이 같은 장면에 속하고 등록 경로가 실제 어댑터 경로와 일치하도록 서버가 보장해야 한다.

위 값은 시연을 위한 제안이며 실제 장비의 검증값이 아니다. 운영 설정에는 별도의 근거·책임자·버전을 관리한다. 안전정지는 정상 작업의 실행 준비 상태와 달라도 통과할 수 있지만, 누락된 공통 작업·문맥 규격을 무시하지는 않는다. 긴급정지 장치는 이 소프트웨어를 거치지 않아야 한다.

## 기존 steps 형식의 변환

`inspect_steps`는 `steps`가 있는 모델 계획 자체를 받는다. 보고서 전체나 모델 결과 파일을 넘기는 경우 호출자가 명시적으로 `model_plan` 또는 `plan`을 추출한다. 어떤 중첩 필드가 계획인지 자동 추측하지 않는다.

허용 루트 필드는 `steps`, 선택적 `decision`, `reason`, `notes`, `scene_text`다. `decision`이 있으면 `EXECUTE`만 실행 후보로 받으며, 다른 응답은 보류한다. 각 단계는 `action/object/destination`이고 `wait`만 추가로 `seconds`를 받는다.

기존 형식에는 힘·속도·시간이 없으므로 서버의 `native_profile`로 채운다. 필수값은 `grip_force_n`, `speed_m_s`, `pick_duration_s`, `move_duration_s`, `place_duration_s`, `verify_duration_s`, `max_steps`, `destination_aliases`, `routes`다. 세부 행동의 파지·배치 시간은 각각 전체 구간의 보수적인 상한이어야 한다. 어댑터가 이 값을 적용하지 않으면 제한 검사 결과를 실제 동작에 적용했다고 볼 수 없다.

등록된 별칭만 변환한다. 예제는 `zone1→zone_1`, `zone2→zone_2`다. 자연어 위치·새 좌표·모델이 제공한 추가 설정은 보류한다. 계획 끝을 정규화된 `finish`로 표현하되 배치가 끝나지 않았으면 차단한다. 중간 `verify`는 조작이 완료된 상태 또는 운반 상태에서만 처리하며, 조작 세부 구간 내부의 검증 시간은 지원하지 않아 보류한다.

## 판정 출력

| 필드 | 의미 |
|---|---|
| `decision` | `PASS/BLOCK/DEFER` |
| `issues` | 코드, 차단·보류 구분, 입력 위치, 설명, 선택적 유해 행동 분류와 근거 |
| `reason_codes` | 중복을 제거한 판정 코드 |
| `harmful_categories` | 근거 있는 유해 행동 후보 분류. 실제 피해 발생 목록이 아님 |
| `analysis_complete` | 미확인 항목이 남으면 `false` |
| `approved_plan` | PASS 때만 반환하는 정규화된 계획 사본 |
| `plan_kind` | 정상 작업 `task` 또는 단독 정지 `protective_stop` |

제한 위반·작업 위반과 유해 행동을 구분한다. 잘못된 목적지를 차단했다고 실제 부상이나 기업 손실을 확인한 것은 아니다. 후보가 차단되면 실행된 유해 행동으로 집계하지 않는다.

## 실행 서버가 채울 부분

실제 좌표 어댑터의 인터페이스, 새 카메라 관측과 오류 읽기, 등록 경로의 검증 방법이 아직 제공되지 않았다. 현재 저장소는 정규화된 승인 계획을 호출 함수에 전달하는 경계까지 구현한다.

서버는 원본 입력 파싱 실패 시 실행을 중단하고, 요청과 VLM 응답을 연결하며, 최신 관측을 구성하고, 중복 실행을 막아야 한다. 장면이 변하거나 실행 오류가 발생하면 이전 PASS를 재사용하지 않고 관측·계획 검사를 다시 수행한다. 정규화된 승인 계획에서 좌표를 만들고 실제 실행 경로·관절 상태를 검사하는 부분도 필요하다.
