# 유해 행동 정의의 F2 적용 범위

> 이전 규칙 검사기 기록입니다. 현재 Contract 구조·검증 상태는 [F2 구현과 연결](F2_구현과_연결.md)을 기준으로 봅니다.

유해 행동은 로봇 또는 실행 시스템의 행동·반복·필요한 행동의 미수행으로 보호 대상에 실제 피해를 주거나, 구체적이고 현실적인 피해 경로가 있는 위험 상태를 만드는 것이다. 이번 행동 계획 필터(F2)는 실행 전 후보를 검사하므로 **실제 부상·파손·금전 피해가 발생했다고 판정하지 않는다.**

이 정의와 여덟 분류는 사용자가 확정한 「다양한 환경의 Harmful Action 정의 v1.0」(2026-10-04)을 적용한다. 분류 자체가 ISO의 공식 분류는 아니며, 세부 표준 조항이나 인증 적합성까지 구현한 것은 아니다.

## 여덟 분류와 구현 범위

| 분류 | 정의 | 현재 구현이 할 수 있는 일 |
|---|---|---|
| 사람 위해(HA1) | 충돌·끼임·압착·낙하물 등으로 사람을 해치거나 구체적인 위해 경로를 만듦 | 신뢰된 접근·운반·배치 근거에 사람 노출과 위해 경로가 제시되면 후보 차단. 사람 검출·거리 계산은 외부에서 제공 |
| 로봇 자체 손상(HA2) | 본체·관절·그리퍼·센서·배선에 손상 또는 근거 있는 손상 위험을 만듦 | 관련 위험 근거가 있으면 후보 차단. 속도·힘 제한 위반도 차단하되 손상으로 자동 분류하지 않음 |
| 물품·설비 손상(HA3) | 파손·변형·오염·기능 상실이나 그 피해 경로를 만듦 | 대상·경로·배치의 손상 위험 근거로 차단. 물리 재질·충격 계산은 미포함 |
| 물체 통제 상실(HA4) | 낙하·튐·비산·굴러감·이탈이 위해·손상·분실 또는 구체적인 위험을 만듦 | 지지·안정성 미확인 시 보류, 실패 확인 시 차단. 구체적인 낙하·분실 근거가 있을 때 해당 분류를 기록 |
| 승인되지 않은 대상 조작(HA5) | 조작 권한이 없는 대상에 행동하여 피해·통제권 상실 또는 그 경로를 만듦 | 대상·권한 위반 차단. 피해 경로가 없으면 권한 위반만 기록 |
| 생산·업무·금전 피해(HA6) | 불필요한 반복·점유·중단·재작업·자원 낭비 등으로 손실 또는 그 경로를 만듦 | 횟수·계획 시간·보유 시간 상한 초과 차단. 실제 손실이나 기업 피해액은 산정하지 않음 |
| 정보·권한·통제권 침해(HA7) | 무단 공개·기록 훼손·정보 이용 불가·정당한 제어권 박탈을 만듦 | 지원하지 않는 정보·설정 변경 행동은 실행하지 않음. 정보 유출 검사기는 구현하지 않음 |
| 안전 기능과 실행 통제 실패(HA8) | 필요한 정지·차단·확인·경고·허가가 행동을 통제하지 못해 위험을 만듦 | 오류·안전 기능 상태 검사와 PASS 전 전달 차단. 실행 중 감시·허가 재사용 방지는 서버 책임 |

모든 분류를 공통 근거 형식으로 받을 수 있지만, 모든 위험을 자동 검출하는 구현은 아니다. 특히 관절 한계·가속도·배선 누적 회전·실제 반복 고장·정보 유출은 현재 입력 규격만으로 자동 판단하지 않는다.

## 단순 위반과 피해 경로 구분

잘못된 대상·목적지, 속도 제한 초과, 반복·시간 상한 초과는 실행 차단 사유다. 이것만으로 부상·파손·금전 손실을 주장하지 않는다. 공격 의도는 필수 조건이 아니며, 인식·계획 오류도 같은 규칙으로 검사한다.

사람 작업 구역·보호 공간·금지 구역에 들어간 사실 자체는 승인되지 않은 대상 조작 분류에서 제외한다. 등록된 작업 제약 위반으로 차단할 수 있고, 사람 충돌이나 설비 손상의 구체적인 경로가 있으면 해당 분류를 추가한다.

정당한 보호 정지는 작업 지연만으로 생산·금전 피해에 넣지 않는다. 구현에서도 단독 `stop`은 `protective_stop`으로 구분한다. 결과가 PASS여도 정상 작업을 완료했다고 보고하지 않는다.

## 위험 근거 형식

신뢰된 `routes[id].hazards`, `objects[id].hazards`, `regions[id].hazards`에는 다음과 같은 근거를 넣을 수 있다. 대상·배치의 목록은 생략하면 빈 목록으로 취급하며, 경로는 `assessment`와 목록의 일치가 필요하다.

```json
[
  {
    "category": "HA1",
    "evidence": "관측된 작업자의 손과 이 경로의 로봇 링크가 겹쳐 충돌 노출이 확인됨."
  }
]
```

이 문장은 **입력 예시**이며 실제 사람을 관측한 결과가 아니다. 운영 시스템은 보호 대상·조건·원인 행동·피해 경로·현실적인 발생 조건·관측 근거를 확인한 뒤 입력해야 한다. 현재 코드는 분류와 근거 문자열의 존재를 검사할 뿐, 그 내용의 진실이나 기하학적 성립을 증명하지 않는다. VLM 설명에서 이 목록을 만들면 독립 검증 근거가 되지 않는다.

차단된 계획은 유해 행동 후보 차단으로 기록한다. 실행된 위험 상태, 실제 피해와 그 금액은 별도의 실행·검사 기록으로 확인한다. 여러 분류가 붙어도 사건 수나 피해액을 중복 합산하지 않는다.
