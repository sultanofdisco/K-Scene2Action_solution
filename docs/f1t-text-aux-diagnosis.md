# SafeText 텍스트 보조학습 실패 원인 진단

작성일: 2026-10-05

## 1. 결론

**현재 확인된 핵심 실패는 학습한 사례에서 얻은 구분 능력이 새로운 위험 유형으로 이어지지 않는다는 것이다.** 학습 정확도는 86.1%이고, 반복 학습을 늘리면 100%에 도달한다. 그러나 검증 정확도는 50.0%에서 56.3%로만 올라간다.

가장 유력한 원인은 적은 학습 데이터, 학습과 검증 사이의 위험 유형 차이, 고정된 범용 임베딩으로 위험 행동의 차이를 학습하는 구조가 함께 작용한 것이다. 실험으로 확인한 실패 양상과 원인에 대한 해석을 아래에서 구분한다. 이번 결과만으로 CLIP 자체가 안전성 분류에 부적합하다고 확정할 수는 없다.

이번 진단 대상은 **SafeText 텍스트 전용 보조 분류기**다. 이미지와 명령을 함께 받는 기존 F1-T 전체의 평가 결과가 아니다. 보조학습은 고정된 다국어 CLIP 텍스트 인코더 뒤의 별도 MLP만 학습하며, 기존 F1-T나 CLIP 인코더를 개선한 상태도 아니다.

## 2. 실제 학습 조건

| 항목 | 설정 |
|---|---|
| 데이터 | SafeText에서 선별한 52개 상황의 정상/위험 행동 쌍, 총 104개 |
| 분할 | 학습 72개, 검증 16개, 시험 16개 |
| 입력 | 상황과 제안된 행동을 합친 영어 텍스트 |
| 정답 의미 | 해당 상황에서 행동이 안전한지 여부. 악의적 의도나 인젝션 여부와는 다름 |
| 인코더 | `sentence-transformers/clip-ViT-B-32-multilingual-v1`, 가중치 고정 |
| 학습 대상 | 512차원 입력을 받는 MLP, 은닉층 128, 출력 1 |
| 학습 파라미터 | 65,793개 |
| 기본 실험 | CPU, 30 epoch, seed 42, 판정 기준값 0.5 |

전체 공개 자료가 모두 학습에 투입된 것은 아니다. 실제 학습은 72개, 서로 다른 상황으로는 36개뿐이다. 특히 배터리는 4개, 통제되지 않은 화재는 2개로 유형별 학습량도 작다. 원본 안전성 라벨과 자동 검토를 사용했으며, 사람이 모든 정답을 확정한 데이터는 아니다.

## 3. 확인된 실패 양상

### 3.1 학습 사례는 맞히지만 새로운 유형에는 적용하지 못한다

같은 데이터와 구조에서 학습 횟수만 바꿨다. 아래는 seed 42의 결과다.

| 학습 횟수 | 학습 정확도 | 검증 정확도 |
|---|---:|---:|
| 30 epoch | 86.1% | 50.0% |
| 100 epoch | 97.2% | 56.3% |
| 300 epoch | 100.0% | 56.3% |

seed 7과 19에서도 300 epoch의 학습 정확도는 100%, 검증 정확도는 56.3%였다. 현재 결과를 단순한 학습 횟수 부족이나 특정 초기화의 문제로 설명하기 어렵다. 30 epoch에서 덜 학습된 부분은 있지만, 더 오래 학습해도 일반화 문제는 해결되지 않았다.

### 3.2 검증하는 위험 유형이 학습에 아예 없다

| 구분 | 포함된 위험 유형 |
|---|---|
| 학습 | 세정 화학물질, 뜨거운 기름, 실내 연소, 가스와 경보, 전기 접촉, 배터리, 통제되지 않은 화재 |
| 검증 | 압력 용기, 날카로운 물체 |

누수를 막기 위해 위험 유형 전체를 분리했다. 따라서 현재 검증은 이미 배운 위험 유형의 새로운 문장보다 훨씬 어려운 **미학습 위험 유형에 대한 일반화**를 측정한다. 이 평가 목적 자체는 유효하지만, 72개 사례를 학습한 보조 분류기의 기본 성능과 같은 의미로 해석하면 안 된다. 처음 실험을 제시할 때 이 한계를 더 분명히 설명했어야 한다.

추가로 원래 학습 데이터 안에서만 상황을 다시 나누어, 검증 유형이 학습에도 존재하는 실험을 했다. 정상/위험 쌍은 함께 묶고 동일한 행동 문구도 분할 사이에 겹치지 않게 했다. 3개 seed와 30/300 epoch 조합의 검증 정확도는 **62.5~75.0%**였다.

이는 유형 차이가 성능에 영향을 준다는 해석을 뒷받침하지만 확정적인 원인 분리 실험은 아니다. 검증 대상과 학습량이 달라졌고 검증 표본도 12~16개뿐이다. 기존 50%와 직접 비교해 개선 성능으로 발표해서는 안 된다.

### 3.3 같은 상황의 정상 행동과 위험 행동에 같은 판정을 내린다

원래 검증 데이터는 정상/위험 행동 8쌍이다. 기본 모델은 **8쌍 모두에서 쌍 안의 두 행동을 같은 등급으로 분류**했다. 각 쌍에서 하나씩 틀려 정확도가 정확히 50%가 됐다.

점수는 MLP가 낸 위험 점수이며, 실제 위험 확률로 보정된 값은 아니다. 0.5 이상이면 위험으로 분류한다.

| 상황 | 정상 행동의 점수 | 위험 행동의 점수 | 결과 |
|---|---:|---:|---|
| 스프레이 캔 사용 | 사용 전 흔들기: 0.681 | 가열하기: 0.622 | 둘 다 위험, 정상 행동의 점수가 더 높음 |
| 칼의 날카로움 확인 | 토마토 잘라보기: 0.547 | 칼날을 따라 손가락 움직이기: 0.547 | 둘 다 위험, 점수 차이는 약 0.0007 |
| 칼을 들고 이동 | 사람을 향하지 않게 하기: 0.433 | 덜 오래 들도록 더 빨리 움직이기: 0.498 | 둘 다 정상 |

8쌍 중 3쌍은 정상 행동의 위험 점수가 오히려 높았다. 상황이나 물체의 공통점에 비해 행동이 바꾸는 위험 차이를 충분히 반영하지 못한다는 해석과 일치한다. 다만 이것만으로 모델이 특정 단어에 의존한다고 단정할 수는 없다.

### 3.4 임계값 조정만으로 해결되지 않는다

검증 정답을 이미 알고 있다는 조건에서 판정 기준값을 바꿔 얻을 수 있는 최고 정확도도 62.5%, 즉 16개 중 10개였다. 이는 원인 확인을 위한 낙관적 상한이며, 공정한 평가 성능이나 채택할 기준값이 아니다. 위험 점수의 순서가 뒤집힌 사례가 있으므로 기준값 0.5만의 문제는 아니다.

## 4. 구조와 데이터에서 의심되는 원인

### 4.1 적은 사례로 넓은 위험 지식을 학습하도록 요구했다

학습 상황은 36개이며 검증에는 새로운 위험 유형이 등장한다. 65,793개 파라미터를 가진 MLP가 학습 사례를 외우는 것은 가능하지만, 배운 적 없는 물체와 행동의 위험 관계까지 추론한다는 보장은 없다. 파라미터 수만으로 실패를 설명할 수는 없으나, 학습 정확도와 검증 정확도의 차이는 일반화 부족을 직접 보여준다.

### 4.2 CLIP의 기본 학습 목적은 행동 안전성 판단이 아니다

사용한 인코더는 다국어 텍스트를 CLIP 이미지와 대응하는 벡터 공간으로 옮기는 모델이다. 이미지와 문장의 의미적 대응을 학습한 표현에 안전성 구분이 충분히 드러나 있는지는 별도로 검증해야 한다. [공식 모델 카드](https://huggingface.co/sentence-transformers/clip-ViT-B-32-multilingual-v1)

현재는 인코더를 고정했기 때문에 위험 구분을 위해 표현 자체를 조정하지 않는다. 같은 상황을 공유하는 정상/위험 문장 임베딩이 매우 비슷한 쌍도 확인했다. 그러나 높은 유사도가 안전성 정보의 부재를 증명하지는 않는다. 현재 표현으로도 학습 데이터를 100% 맞힐 수 있으므로, 정확한 진단은 ‘현재 데이터와 학습 방식으로는 새로운 위험 차이를 안정적으로 분리하지 못했다’다.

E5나 다른 인코더와 같은 조건으로 비교하지 않았으므로, 지금 모델을 교체하면 해결된다고 주장할 근거도 없다.

### 4.3 상황 문구나 MLP 복잡도 하나만의 문제도 아니다

| 추가 실험 | 원래 검증 데이터의 정확도 | 해석 |
|---|---:|---|
| 상황을 빼고 행동만 인코딩, 30 epoch, 3개 seed | 모두 56.3% | 상황 문구를 제거하는 것만으로 해결되지 않음 |
| 같은 임베딩에 로지스틱 회귀, C=1 | 62.5% | 단순한 분류기도 충분한 성능을 확보하지 못함 |
| 같은 임베딩에 로지스틱 회귀, C=100 | 56.3% | 분류기 설정만 바꾸는 접근에 한계가 있음 |

이 실험들은 이미 확인한 검증 데이터에 반복 접근한 진단이다. 후보 모델의 독립적인 성능 증거로 쓰지 않는다. 행동만 남기면 ‘그것을 가열하라’에서 그것이 무엇인지 사라지는 문제도 있어, 행동만 입력하는 구성을 채택하지 않았다.

## 5. 구현 오류 확인 결과

학습과 검증의 88개 입력을 원문에서 다시 인코딩하여 기존 캐시와 대조했다.

| 검사 | 결과 |
|---|---|
| 데이터 행과 임베딩 메타데이터 순서 | 일치 |
| 원본 safe/unsafe와 숫자 라벨 연결 | safe=0, unsafe=1로 일치 |
| 재계산한 임베딩과 캐시의 최대 절댓값 차이 | 약 0.000000179 |
| 학습/검증 최대 토큰 수 | 45, 모델 한도 128 이내 |
| 기존 체크포인트 재로딩 | 기존 검증 결과 재현 |
| 원본 데이터, 캐시, 체크포인트 해시 | 저장된 값과 일치 |

검사한 범위에서는 입력 순서가 어긋났거나, 라벨이 뒤집혔거나, 문장이 잘려서 실패했다는 증거가 없었다. 모든 구현 오류가 없음을 증명한 것은 아니다. 또한 라벨의 형식적 연결이 맞다는 사실은 개별 사례의 안전성 정답까지 보증하지 않는다.
본 체크포인트를 교체하지 않았으며, 시험 데이터로 학습하거나 성능을 측정하지 않았다. 캐시 생성 단계에서 시험 입력의 고정 임베딩이 만들어져 있지만, 이번 진단의 학습과 점수 계산에서는 제외했다.
